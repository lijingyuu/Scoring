# 羽毛球状态机与赛制全生命周期混沌测试指南

> **适用对象**：负责羽毛球模块无人值守跑批、白天复现定位与缺陷修复的 AI Agent 及人类工程师。  
> **核心目标**：提供与排球同水平的百场至千场级羽毛球无头混沌测试指南，覆盖从赛事创建、名单录入、赛程编排、双轨记分进行、结果结算与提前终局、小组赛排名推进到淘汰赛生成全生命周期。

---

## 1. 架构速览与测试分层

羽毛球与排球不同，包含**前端双轨记分状态机**与**后端全生命周期赛制引擎**：

```
[Layer 1 前端通用记分板混沌]  -->  badminton-fuzzer.js + badminton-fuzzer.test.js
[Layer 2 前端接力追分专项混沌]  -->  badminton-relay-fuzzer.test.js
[Layer 3 后端全生命周期混沌]  -->  BadmintonFullLifecycleChaosTest.java
[Layer 4 分块编排器与看门狗]  -->  frontend/scripts/run-bad-fuzz-batch.mjs
```

### 核心工具与文件位置
- **调研基准**：`docs/badminton-chaos-调研.md`
- **通用记分板 Fuzzer 内核**：`frontend/src/pages/scoreboard/badminton-fuzzer.js`
- **通用记分板 Vitest 测试套件**：`frontend/src/pages/scoreboard/badminton-fuzzer.test.js`
- **接力追分专项 Vitest 测试套件**：`frontend/src/pages/tournament/badminton-relay-fuzzer.test.js`
- **分块批量编排器**：`frontend/scripts/run-bad-fuzz-batch.mjs`
- **后端全生命周期混沌用例**：`backend/src/test/java/com/scoring/backend/engine/BadmintonFullLifecycleChaosTest.java`
- **报告输出目录**：`outputs/fuzz-badminton/`（包含 `fuzz-summary.json`、`fuzz-anomalies.json`、`run-manifest.json`、`chunks/<baseSeed>/`）

## 2. 常用操作命令

所有命令均在项目根目录或对应子目录下执行：

```powershell
# 1. 前端通用记分板单场冒烟 / 指定 seed 复现（单场纯无头仿真，<1秒/场）
npm --prefix frontend test -- src/pages/scoreboard/badminton-fuzzer.test.js

# 2. 前端接力追分赛专项混沌测试
npm --prefix frontend test -- src/pages/tournament/badminton-relay-fuzzer.test.js

# 3. 后端全生命周期混沌测试（创建->名单->赛程->模拟完赛->提前终局->排名->淘汰树）
#    -Dchaos.scale 控制每类赛制生成的比赛组数（默认 50，千场级传 200）
mvn test -Dtest=BadmintonFullLifecycleChaosTest -Dchaos.scale=50 -Dchaos.seed=20260918

# 4. 百场至千场批量仿真：分块编排器（推荐执行侧夜间值守使用）
#    - 每块独立进程（4GB 堆上限 / 块级超时控制），强制触发垃圾回收
#    - 支持断点续跑：中断后重执同一命令自动跳过已完成块
#    - 建议种子段起点 200,000,000，避开排球的 1001 ~ 100,000,000 区间
cd frontend
node scripts/run-bad-fuzz-batch.mjs --total 600 --chunk 100 --base-seed 200000000

# 5. 查看批量运行进度
# 观察 outputs/fuzz-badminton/run-manifest.json
```

## 3. 异常产物结构解析

运行完毕后，会自动在 `outputs/fuzz-badminton/` 生成核心报告：

### 1) `fuzz-summary.json`（总体统计与覆盖度证据）
```json
{
  "baseSeed": 200000000,
  "matchCount": 1000,
  "stats": {
    "totalRallies": 84200,
    "totalUndos": 10500,
    "totalSideSwitches": 4200,
    "criticalMatches": 0,
    "cleanMatches": 1000
  },
  "coverage": {
    "reloads": 312,
    "decidingGameSideSwitched": 145,
    "decidingGameSideKept": 38,
    "deepUndos": 850,
    "hostileRejected": 420,
    "capHits": 88,
    "retirements": 25,
    "gamesHistogram": { "1": 120, "2": 510, "3": 370 }
  },
  "criticalSummary": []
}
```

### 2) `fuzz-anomalies.json`（异常详单与 100% 动作复现链路）
包含所有断言违规场的完整回放链路：
- `seed`: 随机种子（100% 幂等复现）
- `rules`: 局制参数（bestOf, pointsToWin, capPoint, enableDeuce）
- `actionHistory`: 发生异常前的完整时序流水（包含动作类型、小分、发球方、入参）
- `anomalies`: 违反的不变式列表（如 `SCORE_OVER_CAP`, `SERVE_OWNERSHIP_MISMATCH`, `SIDE_SWAP_CONSISTENCY`）
- `stateSnapshot`: 报错时刻的状态快照

## 4. 接手 Agent 的标准作业程序 (SOP)

```
[第 1 步: 读取报告] ──> [第 2 步: 单场复现] ──> [第 3 步: 源码溯源] ──> [第 4 步: 补全单测] ──> [第 5 步: 修复与验证]
```

### 步骤 1：读取并归纳异常报告
- 读取 `outputs/fuzz-badminton/fuzz-anomalies.json` 中的 `critical` 列表。
- 提取代表性异常类型（例如：深撤销后场地未镜像还原、比分超上限、决胜局换边弹窗未锁分等）。

### 步骤 2：使用 Seed 单场高保真复现
在终端运行单场指定 seed 命令，观察报错输出：
```powershell
# 传入报错的 ANOMALY_SEED
npm --prefix frontend test -- src/pages/scoreboard/badminton-fuzzer.test.js -t "seed <ANOMALY_SEED>"
```

### 步骤 3：查看 Action 时序，反查源码
- 查看 `actionHistory` 在出错前发生的操作。重点观察：是否有换边（`SWITCH_SIDES` / `DECIDING_GAME_SWITCH`）、深撤销（`DEEP_UNDO`）或局间切换（`CONFIRM_GAME_END`）。
- 结合 `pages/scoreboard/index.vue`、`relay-scoring.js` 或后端 `MatchSettlementService` 定位逻辑漏洞。

### 步骤 4：编写最小单元复现测试
- 编写聚焦该具体动作链路的单测，确保在未修复时必定红（Red）。

### 步骤 5：修改代码并通过验证
- 实施修复，重新运行全量单测保持全绿（Green）。
- 按照 `type(scope): 一句话结论` 规范提交。

## 5. 执行侧接线与值守建议

若执行侧 Agent 接入定时夜间巡检任务：
1. **种子段划分**：建议从 `200,000,000` 开始，批次间按 `10,000,000` 步进（如 `200000000`, `210000000`, `220000000`...），与排球历史批次永不碰撞。
2. **三层轮换建议**：
   - 轮次 1：羽毛球常规记分百场批（`run-bad-fuzz-batch.mjs --total 100`）；
   - 轮次 2：后端全生命周期赛制引擎混沌（`mvn test -Dtest=BadmintonFullLifecycleChaosTest -Dchaos.scale=100`）；
   - 轮次 3：接力追分赛专项混沌批（`badminton-relay-fuzzer.test.js`）。
3. **内存与超时**：羽毛球为纯数学与状态机逻辑，无需排球的 12 人站位图渲染，单场耗时远低于排球（约 10~50 毫秒/场，百场通常 5~15 秒完成）。超时时间配置 5 分钟即可，块级内存安全裕量极大。
