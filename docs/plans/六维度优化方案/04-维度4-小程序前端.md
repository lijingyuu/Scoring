### 1.3 问题模式归纳（软件工程视角）

1. **「util 已备而无人用」是最廉价的 DRY 修复**：①的收敛不需要写新抽象，只需把 21 处内联副本换回既有 util——先乱码恢复（确认语义）再收敛，一次提交闭环。
2. **样式债的正确单位是「令牌层 + 棘轮」，不是「一次替换」**：约 500 处色值在**零 UI 自动化测试**下不可能安全地一次替换；先立令牌（新代码强制走变量）+ 棘轮（存量计数只降不升），热点页面渐进。
3. **巨页是巨类的镜像**：仓库已有成熟解法（14 页已分层），pkg-create 只是被漏掉的最后一个——按既有范式补齐即可，不需要发明新方法。这与维度1「用既有混沌仿真资产做安全网」同构：**优先复用仓库已验证的模式**。

### 2.2 非目标

- ❌ 不一次性替换全部约 500 处色值（零 UI 测试下回归不可控，棘轮渐进）
- ❌ 不引入业务组件库抽象/原子化 CSS（UnoCSS/Tailwind 对 uni-app 有兼容成本，单人项目负收益）
- ❌ 不给 26 个页面补 UI 自动化（E2E 维护成本 > 单人收益；用「纯函数单测 + 试点目检清单」替代，见 §5 Phase 0）
- ❌ 不动请求层架构（单出口 + 401 闭环是资产，只在其上增能力）

## 3. 候选策略（3 个）

### 策略 A：止血卫生包（复制 + 乱码 + 令牌落纸）

**思路**：只做 G1/G2/G3 的「落纸」部分（令牌定义 + 新代码约束），不做 pkg-create 分层，不做 P3。

**理论依据**：DRY；最高性价比优先。

**优点**：~8h 两周内完成；21 份复制（约 800 行）一次消掉；风险极低。

**缺点**：2285 行巨页原样保留且持续生长（维度1 已证明「不拆的巨类只会长」——1323→1583）；P3 中防重复提交、schemaVersion 属正确性相邻项，拖延即隐性风险；面试叙事只有「收敛重复」一环。

**成本**：⭐（8h）｜投产价值：中｜面试价值：低中｜风险：极低

### 策略 B：卫生包 + 工程化升级（令牌棘轮 + 巨页分层 + P3 收尾）★ **推荐**

**思路**：A 全部 + 三件增量：①色值棘轮守门与热点替换（新代码强制令牌、存量只降不升）；②pkg-create 按**仓库既有「页面 + 可测模块」范式**分解（14 个已分层页面是现成模板与验收对照）；③P3 六项按性价比排序收尾。

**理论依据**：
- DRY 收敛 + 试点-铺开（Pilot then Rollout）：21 页先 1 页试点目检，再机械铺开；
- 设计令牌（Design Tokens，Salesforce/Studio Aux 已普及的样式单源思想）：色值从「每处独立决定」变「引用语义令牌」；
- 特征测试 + 既有范式复用（Feathers 思想的小型应用）：pkg-create 分解前先钉行为，分解模板抄 14 个已分层页面；
- 棘轮守门（与维度1 行数棘轮、维度2 校验守门、维度3 表数断言同一制度思想）：约束靠脚本不靠自觉；
- Single-Flight 模式解决 onShow 并发 fetch。

**优点**：消除全部 P2；巨页止血并接入仓库成熟范式；P3 一并清账；每步独立可交付；面试叙事完整（DRY→令牌→分层→守门四环）。

**缺点**：总周期 5 周；pkg-create 分解需要特征测试铺垫（约 3h）；色值棘轮有白名单维护成本（图片 url、uni.scss 本身等误报源）。

**成本**：⭐⭐⭐（~26h/5 周，多数为机械替换可碎片时间执行）｜投产价值：高｜面试价值：高｜风险：中低

### 策略 C：全面前端重构

**思路**：481 处色值一次替换 + 14 个巨页全部重新分层 + 页面级模式抽业务组件库 + 引入原子化 CSS。

**优点**：终态最「现代」。

**缺点**：①约 500 处色值全量替换 + 组件库抽象在**零 UI 自动化**下回归面不可控（26 页全靠手点）；②14 个巨页「已分层」——重分是伪需求（诊断确认它们健康）；③原子化 CSS 与 uni-app 小程序端的兼容验证成本由单人承担；④工作量 60h+，挤压真正的高价值项（后端三维度）。**典型过度工程**。

**成本**：⭐⭐⭐⭐⭐（60h+）｜投产价值：不升反降｜面试价值：低（讲不出验证手段的大改是负资产）｜风险：高

## 4. 加权决策矩阵与选型结论

权重沿用全局（投产 0.30 / 面试 0.25 / 成本 0.25 / 风险 0.10 / 可维护 0.10）。

| 评分维度（权重） | 策略 A 卫生包 | 策略 B 卫生+工程化 | 策略 C 全面重构 |
|---|---|---|---|
| 投产价值（0.30） | 3.5 | **4.5** | 2.5 |
| 面试展示价值（0.25） | 2.5 | **4.5** | 3.0 |
| 实现成本可行性（0.25） | **5.0** | 4.0 | 1.0 |
| 风险安全度（0.10） | **5.0** | 4.0 | 1.5 |
| 长期可维护性（0.10） | 3.0 | **4.5** | 4.0 |
| **加权总分** | 3.70 | **4.35** | 2.45 |

**选型结论：策略 B**。关键论证：pkg-create 是本维度唯一「结构性的」欠账（其余全是卫生债），策略 A 放着它不管等于复制维度1「巨类恶化」的历史；而策略 C 的主体工作（全量替换、健康巨页重分）在零 UI 测试约束下风险定价为负。B 以 +18h 于 A 的成本增量，包圆全部 P2/P3 与唯一的结构项。

## 7. 面试叙述要点（STAR 法）

- **S（情境）**：投产中的 uni-app 小程序（26 页、3 分包），审计发现 21 份被复制的页面样式函数（util 存在却零引用，约 800 行重复）、22 文件乱码注释、481 处硬编码色值（uni.scss 还是脚手架默认）、唯一未分层的 2285 行创建页。
- **T（任务）**：在**没有 UI 自动化测试**的约束下消除重复与样式债，并阻止巨页继续恶化。
- **A（行动）**：
  1. 依赖顺序倒排：先恢复乱码注释（拿到「为何复制」的决策上下文）→ diff 抽查确认 21 份副本与 util 无语义漂移 → 补纯函数单测 → 1 页试点 + 4 项目的检清单 → 20 页机械铺开 → grep 守门防复发；
  2. 样式债用「设计令牌 + 棘轮」而非全量替换：令牌层立即可用（新代码强制），存量靠「基线 529 只降不升」的 CI 守门自然收敛——把不可控的大爆炸改造成可控的梯度下降；
  3. 巨页分解复用仓库既有「页面 + 可测模块」范式（14 个已分层页面是活模板），特征测试先行；
  4. 克制的非目标：论证为什么不引 UnoCSS/不做 26 页 UI 自动化（单人维护成本）。
- **R（结果）**：约 800 行重复消除、色值进入棘轮通道、2285 行巨页降到 ≤600 行壳 + 3 个可测模块、主包体积下降、三个守门进 CI。
- **可被追问的深度点**：无 UI 测试下的安全替换策略（纯函数单测/试点/目检清单三层）；design token 与直接变量替换的区别（语义层 vs 值层）；uni-app 分包与主包体积约束；single-flight 与防抖的区别（并发共享 vs 时间窗合并）。
