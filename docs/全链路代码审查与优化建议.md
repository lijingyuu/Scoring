## 2. 后端安全链路（✅ 已完成）

### 2.1 端点 × 鉴权矩阵（结论摘要）

- `AuthInterceptor` 对 `/api/**` 只做"有 Bearer 则解析、无则放行"（`AuthInterceptor.java:26-34`），强制鉴权在 Controller 的 `AuthGuard.requireUserId()` + Service 层 Guard；JWT HS256，claims 仅 `userId`+`exp`，**无角色字段**。
- 限流两桶：login（登录类 POST，prod 20/min）、write（POST/PUT/DELETE/PATCH，prod 60/min）；GET 与 `/uploads/**` 不限流。
- **所有写端点均有人鉴别权 + 对应 Guard，未发现漏保护的可匿名写端点**；公开端点白名单（`AuthInterceptor.java:42-48`）与限流 login 清单对齐；归档赛事仅创建者可读；记分写操作另需执裁锁。

### 3.3 权限模型核心结论

- **admin-web 不是管理员后台，后端没有"管理员"概念**——不存在垂直越权（所有接口对所有登录用户同一套权限）。写操作后端属主校验逐一 trace 过（归档/编辑队伍/排名配置/裁判管理=创建者；生成淘汰赛/记分/战报=创建者或裁判；归档只读），**未发现漏挂守卫的写端点**，且有集成测试覆盖。
- 残余风险：① 30 天 JWT + 纯前端登出；② "Admin"品牌给未来开发埋的错觉——将来把删除赛事等管理操作搬上 Web 时，必须保持"后端属主校验为唯一防线"。

### 3.4 product-web

隐私合规干净（无第三方统计/表单/iframe）；39 张截图无断链死资源；文案逐条抽查无夸大失实；页脚有免责声明。P3：无 meta description/og/robots/sitemap；侧栏目录锚点靠 JS 运行时补，禁 JS 时导航失效。
