# 真实比赛试跑清单

> **用途**: 拿去跑一场真实的校园班赛 / 院系赛，用它验证产品、收集反馈、沉淀简历素材。
> **核心心态**: 你不是去「演示」，是去「找问题」。凡是让你或对方皱眉、犹豫、需要口头解释的地方，都记下来——那些就是下一步该做的功能。

---

## 1. 这场试跑想验证什么（先写下来）

- [ ] 一个**第一次用的人**能不能不用你讲解，自己走完「创建 → 记分 → 结束」？
- [ ] 记分操作在**真实比赛节奏**下跟不跟得上（对方追着报分的时候）？
- [ ] 哪些环节你在旁边**口头打补丁**了（「这里点这个」「别管那个弹窗」）？
- [ ] 比赛结束后，战报/签名/归档这条链是不是真的有人愿意用？

---

## 2. 赛前准备

### 2.1 设备与网络

- [ ] 记分设备：横屏优先（Pad 或横屏手机），提前锁定屏幕旋转。
- [ ] 备用设备/充电宝：一场比赛比想象中耗电。
- [ ] 网络：现场 Wi-Fi 不一定稳定，确认断网时记分板本地缓存仍可用（本项目 Storage 离线兜底）。
- [ ] 提前用微信开发者工具或真机把「创建赛事」跑一遍，确认后端可达（生产域名 / 本地）。

### 2.2 账号与权限

- [ ] 记分者账号能登录（微信登录 / 账号注册）。
- [ ] 若需要裁判授权：提前设好裁判密码，并让裁判走一遍「验证 → 获得操作权限」。
- [ ] 确认创建者本人可操作比赛（本应自动放行）。

### 2.3 赛前要确认的产品参数

| 参数 | 你设的值 | 备注 |
|------|---------|------|
| 运动类型（羽毛球/排球） | | |
| 赛制（淘汰赛 / 小组+淘汰 / 纯循环） | | |
| 参赛者类型（个人 / 团体） | | |
| 团体赛模板（苏杯五项 / 接力） | | |
| 每局目标分 / 追分 / 封顶分 | | 默认 21 / 追分开 / 30 |
| 是否三四名赛 | | |
| 小组出线名额 `qualifiersPerGroup` | | |

---

## 3. 全流程验收清单（按阶段勾选）

### 3.1 创建赛事

- [ ] 羽毛球个人赛：粘贴名单（空格/换行/逗号分隔）→ 一键生成签表。
- [ ] 排球：逐队录入（6–12 人/队，球衣号、队长、自由人标记）→ 校验通过。
- [ ] 种子排名、轮空（人数不是 2 的幂时）是否正确。
- [ ] 创建后能回到赛事详情，对阵图/小组赛入口正常。

### 3.2 进入比赛 → 记分

- [ ] 从对阵图/小组赛点进比赛，操作权限校验通过（无权限时提示明确）。
- [ ] 记分板加分、追分、封顶、发球权切换符合预期。
- [ ] 横屏布局在真实设备上不错位、按钮不溢出。
- [ ] 撤销（History Stack）能正确回退，且不把存储打爆。

### 3.3 结束 → 晋级

- [ ] 比赛结束：胜者正确推进到下一场（链表晋级）。
- [ ] 三四名赛：半决赛败者正确进入三四名场。
- [ ] 小组赛全部结束后：积分榜正确，生成淘汰赛成功。
- [ ] 平局时：系统提示「未决并列」，能走「人工指定出线」（资格覆盖）后再生成。

### 3.4 赛后：战报 + 签名 + 归档

- [ ] 战报页填裁判/挑边/签名/日期，能保存草稿。
- [ ] 签名板（canvas）真机手写流畅、保存正常。
- [ ] 「封存战报」成功，封存后不可再改、不可重启比赛。
- [ ] 赛事结束后归档 → 从「我的 → 归档」可见、可取消归档。

## 4. 边界场景专项（挑相关的测）

- [ ] **退赛**：某人/某队中途退赛，排名怎么算（删除 vs 单场判负），比分展示是否合理。
- [ ] **重开比赛**：结束错了能重启，且重启后战报/阵容状态符合预期。
- [ ] **断网记分**：记分中途断网，本地继续记，恢复后同步不重复、不丢。
- [ ] **横竖屏切换**：记分页强制横屏，退回其他页正常。
- [ ] **两人同时操作**（如果可能）：同时点生成淘汰赛/同时结算，是否被锁挡住。
- [ ] **iOS/安卓 + 不同机型**：至少各一台，重点看横屏缩放、按钮热区。

---

## 5. 现场记录模板（发现问题的格式）

> 每发现一个问题，立刻记一行，不要事后回忆。

| 环节 | 现象（发生了什么） | 期望（应该怎样） | 严重度 | 备注/截图 |
|------|-------------------|-----------------|--------|-----------|
| 例：记分 | 对方连续报分，追不上 | 一键 +1 更快/有快捷键 | 高 | 拍视频 |
| | | | | |

**严重度参考**：
- 🔴 **阻断**：流程走不下去，必须现场想办法绕。
- 🟡 **反直觉**：能走完，但需要口头解释或用户犹豫。
- 🟢 **锦上添花**：能用，但可以更好。

---

## 6. 跑完后的复盘（回来后我们一起收）

1. 这场暴露出的 🔴 阻断问题有哪些？有没有现场绕过、绕过方式是什么？
2. 哪些环节你做了「口头打补丁」？对应的产品改进点是什么？
3. 用户/对方主动问过哪些「有没有 XX 功能」？记录下来排序。
4. 有没有出现数据错误（晋级错、排名错、重复事件、缓存串场）？能复现吗？
5. 把这场的过程截图/录屏，作为简历和产品介绍的素材。

---

> 拿到第一场反馈后，优先级通常会是：**修 🔴 阻断 → 补最关键的一个 🟡 → 再考虑加新功能**。别急着堆功能。
