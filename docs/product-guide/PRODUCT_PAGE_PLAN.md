# 产品介绍网页规划

> 本文档专门记录 `docs/product-guide/` 产品介绍网页的结构、内容取舍、视觉偏好和后续重排依据。后续凡是涉及产品介绍页的重要模块、文案、信息架构、视觉方向、功能卖点取舍，都应同步更新本文档。

## 1. 当前目标

产品介绍网页不是接口文档，也不是开发说明，而是面向赛事创建者、裁判和潜在使用者的产品说明页。

页面目标：

- 先用纯文字把产品价值、功能边界和用户流程讲清楚。
- 图片后置，等文字结构稳定后再补真实截图。
- 重点突出“赛事管理闭环”，而不是堆砌代码模块。
- 以浅色产品文档风格为主，使用页面已有橙色体系做强调。

## 2. 已确认的页面偏好

- 顶部导航栏固定在顶部，用户滚动到任何正文位置时都能切换模块。
- 页面内目录使用 sticky 逻辑：初始与正文第一个组件平齐，不遮挡顶部介绍栏；滚动到顶部导航栏下方后吸附。
- 左侧目录应根据滚动位置自动高亮当前正文段落。
- 页面先保留纯文字，不保留图片位置，不放截图占位。
- 介绍栏使用浅色背景、深色文字；当前方向偏浅橙色，和页面橙色强调体系统一。
- 整体避免“两个不同深色块堆叠”的设计。

## 3. 顶部 6 个模块

用户已确定顶部导航改为：

1. 产品概览
2. 通用流程
3. 赛制规则
4. 羽毛球个人赛
5. 羽毛球团体赛
6. 排球赛事

### 3.1 合理性判断

这个 6 模块方案整体合理。

优点：

- “产品概览”负责价值定位，不被具体赛制细节打断。
- “通用流程”承接所有比赛共用的创建、授权、查看、归档流程。
- “赛制规则”把复杂规则集中展示，尤其适合承接小组赛排名模板、生成淘汰赛排阵、循环赛、淘汰赛算法等内容。
- 三个专项模块分别对应用户最容易理解的产品入口：羽毛球个人赛、羽毛球团体赛、排球赛事。
- 比原来的“权限与归档”单独占顶部模块更均衡；权限和归档更适合作为通用流程里的能力，而不是一级产品分类。

风险：

- “通用流程”和“赛制规则”边界容易混。通用流程讲用户操作链路，赛制规则讲系统如何算、如何排、如何阻断错误推进。
- “赛制规则”如果写得过技术，会变成开发文档。页面上应使用产品语言，必要时只露出少量规则关键词。
- “羽毛球团体赛”同时包含苏迪曼杯五项和接力追分，内容量较大，页面内目录需要分清两条赛制。

建议：

- 顶部一级模块维持 6 个。
- 原 `permissions.html` 的内容并入“通用流程”。
- 新增或重命名一个“赛制规则”页面，用来承接排名模板、淘汰排阵、小组赛、循环赛、平局阻断等规则型内容。

## 4. 每个模块建议内容

### 4.1 产品概览

目标：让用户快速明白这是什么、解决什么问题、适合谁。

建议放入：

- 产品一句话：面向校园、院系、俱乐部赛事的羽毛球/排球记分与赛程管理工具。
- 核心痛点：
  - 纸质记分容易错、难复盘。
  - Excel 手动排赛程容易漏轮空、晋级路径不清。
  - 小组出线、淘汰晋级和排名规则靠人工容易争议。
  - 排球轮转、自由人、换边、事件记录人工成本高。
- 核心价值：
  - 创建赛事 → 生成赛程 → 现场记分 → 排名/晋级 → 赛后归档。
  - 打完一场比赛，系统自动更新积分、签表或晋级结果。
- 能力矩阵：
  - 羽毛球个人赛：淘汰赛、小组赛+淘汰、循环赛、普通记分。
  - 羽毛球团体赛：苏迪曼杯五项、接力追分、阵容编排、父比赛结算。
  - 排球赛事：队伍录入、轮次填写、Phone/Pad 记分、事件记录、赛后记录。
- 角色路径：
  - 创建者：创建赛事、配置规则、授权裁判、归档赛事。
  - 裁判：验证授权、进入比赛、记分、保存结果。
  - 观看者：查看赛事大厅、详情、签表、小组赛和记录。

### 4.2 通用流程

目标：讲所有赛事共用的用户操作闭环。

建议放入：

- 登录与资料：
  - 小程序微信登录。
  - H5/Web 账号密码。
  - 资料完善后创建赛事。
- 赛事大厅：
  - 浏览赛事。
  - 搜索赛事。
  - 收藏赛事。
  - 进入详情。
- 赛事创建共用配置：
  - 赛事名称、地点。
  - 运动类型。
  - 赛制类型。
  - 基础计分规则。
  - 可选裁判密码。
  - 赛段规则。
- 赛事详情：
  - 淘汰赛进入对阵图。
  - 小组赛/循环赛进入小组页。
  - 团体赛查看队伍与队员。
  - 已结束排球比赛查看记录。
- 裁判授权：
  - 创建者设置 8 位数字裁判密码。
  - 非创建者输入密码获得该赛事操作权限。
  - 授权作用于整个赛事，不是单场比赛。
  - 写页面进入前通过 `can-operate` 校验。
- 归档：
  - 赛事结束后创建者归档。
  - 归档不删除数据。
  - 归档后只读，创建者和裁判都不能继续写入。
  - 创建者可从归档列表查看和取消归档。

### 4.3 赛制规则

目标：集中解释产品最有差异化的规则能力。

建议放入：

- 三类基础赛制：
  - 纯淘汰赛。
  - 小组赛 + 淘汰赛。
  - 循环赛。
- 淘汰赛排表：
  - 容量对齐到 2 的幂。
  - 种子排序。
  - 轮空坍缩。
  - `nextMatchId / nextMatchSlot` 串联晋级链。
- 小组赛：
  - 自动生成组内循环。
  - 小组排名来自实际比分数据，不只看显示文本。
  - 所有小组赛完成后才能生成淘汰赛。
- 小组赛排名模板：
  - 排名模板按赛制隔离。
  - 羽毛球个人赛、苏杯五项、接力追分、排球各有独立模板。
  - 可选常用模板。
  - 支持自定义模板，但只显示当前赛制允许的指标。
- 平局阻断：
  - 出线边界存在未解决平局时，不允许生成淘汰赛。
  - 两人完全相同优先看 H2H；无 H2H 胜者才标记未解决。
- 小组出线后的淘汰排阵：
  - 收集每组出线者。
  - 第一名按组号升序排列。
  - 第二名按组号降序排列。
  - 避免同组第一和第二首轮相遇。
- 循环赛：
  - 无淘汰赛阶段。
  - 最终排名即比赛结果。

### 4.4 羽毛球个人赛

目标：讲清楚个人/双打参赛单位如何创建、记分和晋级。

建议放入：

- 适用场景：
  - 单打。
  - 简单双打组合。
  - 校园个人赛、班赛、院系赛。
- 名单录入：
  - 一行一名选手。
  - 双打可用一行表示一组搭档。
  - 可带种子顺序。
- 支持赛制：
  - 纯淘汰赛。
  - 小组赛 + 淘汰赛。
  - 循环赛。
- 记分板：
  - 逐分操作。
  - 局分、总比分。
  - 换边、撤销、退赛、结算。
- 结果推进：
  - 小组赛更新积分榜。
  - 淘汰赛胜者自动进入下一轮。
  - 小组出线后生成淘汰赛签表。
- 排名规则：
  - 默认 BWF 模板。
  - 常用模板。
  - 自定义模板。
  - 个人赛不能使用团体赛的场内大分指标。

### 4.5 羽毛球团体赛

目标：把苏迪曼杯五项和接力追分作为两个清晰子能力展示。

建议放入：

- 团体赛共性：
  - 队伍是参赛单位。
  - 队员是队伍明细。
  - 最终晋级和战报归属于队伍。
- 苏迪曼杯五项：
  - 男单、女单、男双、女双、混双。
  - 创建赛事时生成父比赛，不一次性创建所有子比赛。
  - 进入某场团体对抗后编排五项阵容。
  - 单项开始时按需创建子比赛。
  - 子比赛结果回写父比赛。
  - 五项全部完成，或淘汰阶段一方 3 胜，结算父比赛。
- 苏杯排名：
  - 胜场。
  - 场内大分。
  - 场内局。
  - 局内小分。
- 接力追分：
  - 不使用苏杯五个单项。
  - 双方按固定队员顺序组成连续双打段。
  - 整场只累计总分。
  - 相邻段共享队员，最后一段回到第一名队员形成闭环。
  - 达到当前段目标分后切换下一段。
  - 最终目标分达成后结算。
- 接力排名：
  - 胜场数。
  - 两队直胜。
  - 小分得失比。
  - 自定义排名不能显示场内大分和场内局。

### 4.6 排球赛事

目标：突出排球不是普通记分板，而是完整现场执裁工作流。

建议放入：

- 创建排球赛事：
  - 逐队录入。
  - 每队 6-12 人。
  - 球衣号。
  - 队长。
  - 自由人。
  - 淘汰赛、小组赛+淘汰、循环赛。
- 轮次填写：
  - 记分前必须先完成 lineup。
  - 双方 6 个场上位置。
  - 发球方。
  - 自由人绑定。
  - 比赛时间、主裁、副裁。
- 排球记分板：
  - Phone/Pad 两套 UI，核心逻辑共享。
  - 发球方得分不轮转。
  - 接发方得分切换发球权并顺时针轮转。
  - 自由人自动换人或恢复副攻。
  - 换人、暂停、队长变更、换边事件。
  - 决胜局达到换边分提示换边。
  - 结算前强制同步未提交事件。
- 赛后记录：
  - 总比分。
  - 每局比分。
  - 双方名单。
  - 阵容快照。
  - 暂停、换人、换边、队长变更。
  - 签名区。
- 排球排名：
  - 排球模板独立于羽毛球。
  - 常用模板：胜场数 → 胜局数 → 得失分比。
  - FIVB 模板：胜场 → 比赛积分 → 胜负局比 → 得失分比 → H2H → 名字序。

## 5. 推荐的信息架构

推荐每个页面统一使用：

1. 顶部导航
2. 浅色介绍栏
3. 左侧 sticky 页面目录
4. 正文内容区
5. FAQ 或说明重点

页面内常用组件：

- 功能卡片：用于展示独立能力。
- 流程条：用于展示闭环步骤。
- 对比卡：用于解释个人赛/团体赛、苏杯/接力、羽毛球/排球的差异。
- 规则说明块：用于解释平局阻断、排名模板、蛇形交叉。
- 注意事项：用于放容易误解的业务边界。

## 6. 当前最值得突出展示的产品特色

优先级从高到低：

1. 自动晋级闭环。
2. 小组赛排名模板可选、可自定义、按赛制隔离。
3. 小组出线后蛇形交叉生成淘汰赛。
4. 排球专业执裁链路：轮次、自由人、轮转、事件、记录。
5. 苏迪曼杯五项父子比赛结构。
6. 接力追分赛作为特色团体赛。
7. 裁判授权和归档只读。

## 7. 后续改网页时的注意事项

- 不要把 `permissions.html` 继续作为一级导航；权限与归档并入“通用流程”。
- “赛制规则”需要新页面或重命名现有页面，不能只在产品概览里简单带过。
- 产品介绍页不应出现长代码、接口字段堆砌；需要从用户价值角度转译。
- 如果引入截图，应先确定每个模块的文字层级，再按段落补图。
- 图片不应作为信息结构的占位；没有图时页面也必须完整可读。
- 小组赛排名模板和生成淘汰赛排阵是近期新增的产品亮点，必须在产品页中显式展示。
