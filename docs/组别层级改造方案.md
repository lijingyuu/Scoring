## 0. 已确认的设计决策

| 决策点 | 结论 |
|---|---|
| 层级模型 | Tournament（赛事）→ **TournamentDivision（组别）** → MatchRecord（比赛）；组别 = 完整子赛事，赛制+规则全部下沉 |
| 兼容模式 | **默认组别模式**：每个赛事必有 ≥1 个组别；排球/团体等"无组别"赛事 = 只有 1 个默认组别，行为与现在完全等价 |
| 多组别范围 | **v1 仅羽毛球个人赛**（sportType=0 且 participantType=0）允许 >1 个组别；排球/团体强制单组别，报错拦截 |
| 报名形态 | 双打 = 组队报名（Player 直接提交 pair 名），不做后台配对 |
| 组别增删 | 创建时一次性定死，赛后（含未开赛）均不可增删 |
| 裁判授权 | 沿用赛事级：一个裁判密码管整个赛事所有组别，**不改** |
| 赛事状态 | 全部组别完赛 → 赛事完赛；任一组别开赛 → 赛事进行中 |
| 产品入口 | 赛事仍是唯一入口，详情页内部分组别展示（前端后做） |
| 命名 | 代码/表统一用 `division`（`tournament_division`、`division_id`）。**绝不复用 `group`**——现有 `group_no/group_size` 是"小组赛分组"语义，两者无关 |

### 1.1 新表 `tournament_division`

从 `tournament` 下沉的列 + 新增列（完整 DDL，迁移脚本按此写）：

  `status` TINYINT NOT NULL DEFAULT 0 COMMENT '0-not started, 1-running, 2-finished',
  `participant_type` TINYINT NOT NULL DEFAULT 0 COMMENT 'reserved, always 0 in v1',

### 1.2 存量表加 `division_id`（5 张）

统一模式：加列（NULL）→ 回填 → 收紧 NOT NULL → 建索引。**保留 `tournament_id` 列不删**（权限守卫、旧接口兼容、团体赛路径继续使用）。

| 表 | 变更 | 唯一键调整 |
|---|---|---|
| `player` | + `division_id` + `idx_player_division_id` | 无 |
| `match_record` | + `division_id` + `idx_match_division_id` | 无 |
| `tournament_round_rule` | + `division_id` | V15 的 `uk_tournament_round_rule(tournament_id, stage_type, round_num)` → **DROP + 新建** `uk_round_rule_division(division_id, stage_type, round_num)` |
| `tournament_ranking_config` | + `division_id` | `uk(tournament_id)` → `uk(division_id)` |
| `tournament_qualification_override` | + `division_id` | 两个 uk 的 `(tournament_id, group_no, …)` → `(division_id, group_no, …)` |

### 1.3 存量回填（同脚本内）

每个存量赛事恰好建一个默认组别，规则/赛制/状态列从 `tournament` 复制：

```sql
INSERT INTO tournament_division (id, tournament_id, name, sort_order, status, tournament_type, ...)
SELECT CONCAT(t.id, 'D01'), t.id, '默认组别', 0, t.status, t.tournament_type, ...
FROM tournament t;

UPDATE player p JOIN tournament_division d ON d.tournament_id = p.tournament_id SET p.division_id = d.id;
-- match_record / tournament_round_rule / tournament_ranking_config / tournament_qualification_override 同理
```

- 回填 id 格式 `CONCAT(id,'D01')`（19 位雪花 + 3 字符 = 22 位，VARCHAR(32) 内；运行时新组别用 ASSIGN_ID 纯数字，无碰撞）。
- 部署窗口内一次性执行（用户量小，直接随 Flyway 启动迁移）。

### 1.4 `tournament` 表处理

- **不删不改任何列**（迁移零破坏）。
- 下沉列（tournament_type、规则列、current_stage、knockout_generated 等）自 V23 起**不再是业务读写入口**。
  **实施偏差说明**：原计划给这些字段标 `@Deprecated`，实际改为在 `Tournament` 实体类注释中声明"sink 字段"约定，**未加注解** —— 原因：仍有少量合法兜底读取点（`TournamentRuleResolver` 组别缺失时回退赛事规则；`MatchSettlementService` 约 414 行在 `division == null` 时读 `tournament.getTournamentType()`；`TournamentServiceImpl.getTeams` 的团队赛路径），标 `@Deprecated` 会在这些点产生告警噪音，反而弱化信号。新代码**不得**新增对 sink 列的读取（读规则一律经 `TournamentRuleResolver`）。
- `status` 例外：继续作为**聚合状态**维护（见 §5）。
- **单组别镜像写**（回滚保险）：单组别赛事在写 `division.current_stage / knockout_generated / status` 时同步镜像写 `tournament` 同名列。多组别无法镜像（本就超出旧代码能力）。代价极小，换来代码级回滚后旧版本仍可运维单组别赛事。

### 1.5 `schema-h2.sql` 同步

测试库同步新表 + 新列 + 唯一键。

## 3. 创建流程（TournamentCreationFactory，改动核心）

### 3.1 `CreateTournamentReq` 扩展

```java
private List<DivisionSpec> divisions;   // 新结构；为空 = 旧扁平 payload 兼容

public static class DivisionSpec {
    private String name;                      // 必填，组别内唯一
    private List<PlayerEntry> players;        // 该组别报名名单
    private Integer tournamentType;
    private Integer knockoutSlots;
    private Integer knockoutRounds;
    private Integer qualifiersPerGroup;
    private Integer roundRobinRounds;
    private RuleConfig rule;
    private Boolean roundRuleEnabled;
    private List<RoundRuleConfig> roundRules;
    private Boolean thirdPlaceEnabled;
    private RuleConfig thirdPlaceRule;
    private String rankingTemplate;           // 排名规则也组别级
    private List<String> rankingPriorities;
}
```

**兼容规则（关键）**：`divisions == null/空` → 将旧扁平字段（players、tournamentType、rule、roundRules、thirdPlace*、ranking*…）打包成一个匿名默认组别（name = "默认组别"），老小程序 / web 创建页**零改动**。

### 3.1.1 组别模式下顶层字段的处理（避免误传）

| 顶层字段 | 行为 |
|---|---|
| `players` / `teams` / `rule` / `rule` 系列（`roundRules`、`thirdPlaceRule`）/ `rankingTemplate` / `rankingPriorities` / `tournamentType` / `knockoutSlots` 等赛制字段 | **与 `divisions` 同传 → 400 拦截**（防静默丢失；判据见 `TournamentCreationFactory.hasTopLevelPayload`） |
| `name` / `location` / `sportType` / `participantType` / `teamMatchTemplate` / `refereePassword` | 合法：赛事级字段，由 `divisions` 模式正常使用 |
| 其余未列字段 | 无（本版无其它赛事级入参） |

> 说明：拦截判据包含"非空 `teams`"，即 `divisions` 与非空 `teams` 同传也会被拒 —— 多组别仅支持羽毛球个人赛，属预期行为。

### 3.2 校验规则

1. `divisions.size() > 1` 时：`sportType == 0（羽毛球）` 且 `participantType == 0（个人）`，否则 400。
2. 组别名非空、赛事内不重名（DB 唯一键兜底）。
3. 每个组别各自走现有的 `applyTournamentType / applyRule / applyVolleyballRule` 校验（男单可 32 人小组+淘汰、女单可 8 人单淘汰，互不影响）。
4. 组别数上限 16（防呆）。
5. 选手名：组内目前本无唯一性校验、DB 无唯一约束 → **维持现状**。组别间同名天然允许（同一人报男单+男双是正常需求）。

### 3.3 编排改造

```
createTournament:
  1. 归一化：legacy flat payload → 单 DivisionSpec
  2. 校验（§3.2）
  3. persistTournament：只写赛事级字段（name/location/sportType/participantType/
     teamMatchTemplate/creator/referee…）；下沉列写第 1 个组别的值占位（列 NOT NULL）
  4. for each division（按数组序 = sort_order）:
       persistDivision
       persistPlayers(division)        // player 同时写 tournament_id + division_id
       assignGroups                    // 蛇形抽签，组别内独立
       generateMatchesForType          // 引擎按 division 生成
       saveRoundRulesIfNeeded          // round_rule 带 division_id
       saveRankingConfig               // ranking_config 带 division_id
```

- `RoundRobinEngine.generateGroupMatches / generateLeagueMatches` 同理。

`GET /tournaments/{id}`（detail）响应**新增** `divisions` 摘要数组字段（加字段不破坏老前端解析），原有平铺字段照旧填充（取默认组别）。

### 4.2 旧 API 兼容层（老前端零改动，最关键的兼容策略）

旧的 `/{id}/bracket`、`/groups`、`/group-standings`、`ranking-config`（GET/PUT）、`qualification-overrides`、`knockout-preview`、`generate-knockout`、`teams` 全部改为：

```
resolveDefaultDivision(tournamentId)   // 按 sort_order 取第 1 个组别
→ 委托到组别版服务逻辑
```

- 单组别赛事：行为 100% 等价。
- 多组别赛事命中旧接口：返回/操作第 1 个组别（过渡行为，代码注释 + `TournamentServiceImpl.resolveDefaultDivision` 的 debug 日志标记；新前端上线一个版本后下线）。
- 老前端只能创建单组别（旧 payload），因此"多组别 + 旧写接口"实际不会发生。

### 4.3 权限（不改）

`TournamentAccessGuard` / `MatchAccessGuard` / 裁判体系全部沿用 match→tournament 直连（`tournament_id` 列保留的原因）。创建者/裁判 = 赛事级权限，天然覆盖所有组别。

## 5. 状态机与完赛判定（MatchSettlementService，最高风险点）

- `division.status`：0 未开始 / 1 进行中 / 2 已结束（语义同现 tournament.status）。
- `markTournamentRunning(match)`（首场开赛，:486）→ 改为：
  ```
  division.status = 1（幂等）
  tournament.status = 1（幂等）
  ```
- `finishTournamentIfReady`（:295）→ 拆两级：
  ```
  finishDivisionIfReady(current, division):
      if division.thirdPlaceEnabled && 淘汰阶段 && !allTerminalKnockoutMatchesFinished(division.id): return
      division.status = 2                       // selectByIdForUpdate 行锁下更新
      if 该赛事所有 division.status == 2:
          tournament.status = 2
  ```
- `allTournamentMatchesFinished` / `allTerminalKnockoutMatchesFinished`（:589/:613）：查询键 `tournament_id` → `division_id`。
- `clearQualificationOverridesIfRankingMatch`（:493）：delete 键改 `division_id`。
- **并发**：状态更新必须在现有 `selectByIdForUpdate(match)` 事务内、且对 division 行加锁（新增 mapper 方法），避免两个组别同时完赛时聚合判定竞态。
- 团体赛路径 `settleParentTeamMatch` 等不动（单组别下天然兼容）。

## 6. 排名与出线（TournamentRankingService）

| `buildStandingsVO:487` | 维度 tournamentId → divisionId：按 `division_id` 拉 players + stage_type=0 比赛，`groupNo` 分组逻辑不变 |

## 7. 规则解析（TournamentRuleResolver）

`resolveForMatch(tournament, match)` → `resolveForMatch(division, match)`（调用方由 `match.divisionId` 加载 division；排球团体子赛的 `resolveScopeMatch` 逻辑不动）。

解析链（沿用现有 fallback 风格）：

```
季军赛（division.third_place_*）
  → 轮次规则（tournament_round_rule by division_id + stage_type + round_num）
    → division 默认规则
```

`MatchServiceImpl` / `MatchDetailAssembler` 等调用点同步换参。

- 裁判体系（RefereeService / RefereeConfig / RefereeGrant）。
- 收藏、归档、用户、登录、文件上传。
- match 级全部接口（score / lock / heartbeat / events / record / report…）与前端所有 matchId 维度缓存。
- Web 管理端后端兼容（旧 payload = 单默认组别）。

## 9. 测试计划

**单测**：Resolver 三级 fallback；完赛聚合（部分完赛/全部完赛）；默认组别解析；legacy payload 归一化。

**集成（H2）**：
1. 等价性回归：旧 payload 创建 → 对阵/小组/积分榜/排名配置/出线覆盖/生成淘汰赛/完赛 全链路与改造前行为一致（金标准用例）。
2. 多组别：3 组别（男单小组+淘汰、女单单淘汰、男双单循环）各自独立赛程、独立规则、独立排名配置。
3. 状态聚合：组别 A 全完 + 组别 B 未完 → 赛事 status=1；全部完 → 2。
4. 兼容层：多组别赛事命中旧接口 → 返回第 1 组别。
5. 拦截：排球 payload 带 >1 组别 → 400；组别重名 → 400。
6. 排球全流程回归（确认零改动未破）。
7. 组别级排名配置相互独立（A 组改模板不影响 B 组）。
8. 多组别小组赛各自生成淘汰赛（含"小组赛未完拒绝预览""A 组完赛赛事未结束"）。
9. 组别级分轮规则按组别+阶段生效（小组赛 11 分一局 vs 淘汰赛 21 分三局，两组别互不影响）。
10. 季军赛聚合组别隔离（A 组季军赛未完 → A 组不完结、赛事不结束；B 组完赛不被拖住）。
11. 两端 payload 形状（web/小程序）被后端接受并正确落库。

**手工**：老版本小程序（线上包）创建 → 执裁 → 完赛全流程冒烟。

## 11. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 迁移失败 | V23 只加表/加列/回填，不改不删旧列。**注意：非幂等**（MySQL 的 ADD COLUMN/DROP INDEX 不支持 IF NOT EXISTS，回填 INSERT 依赖唯一键防重）——中途失败会留下半执行状态，恢复步骤：①按报错语句人工补齐/跳过已完成语句；②`UPDATE flyway_schema_history SET success=1 WHERE version='23'`（或 flyway repair）后重启。发布前建议先跑孤儿行预检：<code>SELECT COUNT(*) FROM player p LEFT JOIN tournament t ON t.id=p.tournament_id WHERE t.id IS NULL</code>（match_record / tournament_round_rule / tournament_ranking_config / tournament_qualification_override 同理，应为 0） |
| 新代码有 bug 需回滚 | 单组别镜像写（§1.4）保证回滚到旧代码后单组别赛事仍可完整运维；多组别赛事回滚期间不可用（老前端本就建不出，影响面≈0） |
| 完赛聚合竞态 | division 行锁 + 既有 match 行锁同事务；**锁顺序统一 tournament → divisions（按 id 升序）**，与 generateKnockout 一致，防交叉死锁 |
| 旧前端兼容破坏 | 兼容层 + detail 响应只加字段；上线后用线上包全流程冒烟 |
| schema-h2 漂移 | 与 V23 同 PR 提交 |
