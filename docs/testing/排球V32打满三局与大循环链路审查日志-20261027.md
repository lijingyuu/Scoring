- `volleyball.vue`：出线名额步进/输入钳制 `Math.min(4, …)`（+ / input 两处）；`qualifiersPerGroup > 2 && groupCount === 1` 才显示"单组大循环" hint；`groupRule.forceFullGames` 开关仅在 `bestOf === 3` 渲染；`setBestOf` 切离三局两胜时重置开关；payload `forceFullGames: bestOf === 3 && rule?.forceFullGames === true`（淘汰规则无此键 → 恒 false）；提交前镜像后端校验「出线>2 仅单组」（文案与后端一致）。
- `TournamentCreationFactory`：
  - 合法值集合放开为 `{1,2,4}`，`qualifiers > 2 && groupCount != 1` 抛「每组出线超过2名当前仅支持单组(大循环)赛制」；
  - 排球分支 `forceFullGames && bestOf != 3` 400；非排球恒 false（忽略入参）；
  - `applyDivisionRule` 落库 division；镜像列 `tournament.setForceFullGames(division.getForceFullGames())`（创建占位，与 V32 注释一致）。
- `groupCount` 三端语义一致：小程序 `max(1, floor(knockoutSlots/qualifiersPerGroup))` ≡ 后端 `knockoutSlots % qualifiers == 0` 后整除 ≡ admin-web `divisionGroupCount`（共享模块）。
- ✅ 判定：一致、无绕过。

### 链路 2：淘汰赛生成（前 4 种子摆位）
- `BracketEngine.buildKnockoutSlots`：`qualifiersPerGroup >= 3` 分支按 `GroupRank.rank` 升序 + `buildSeedOrder` 摆放；`buildSeedOrder(4)` = `[1,4,2,3]`（递归验证：[1]→[1,2]→[1,4,2,3]），半决赛 1v4 / 2v3，1/2 号种子分居上下半区；入参顺序无关（单测断言乱序入参同结果）。
- `>= 3` 仅单组可达（链路 1 拦多组），同组回避问题不存在（注释已说明，且 `loadGroupedKnockoutContext` 守卫仍在）。
- 手动出线确认：`applyQualificationOverrides` 与并列槽位计算均按 `1..qualifiersPerGroup` 泛化循环，无「最多 2」硬编码，qualifiers=4 兼容 ✅。
- 季军赛挂半决赛负方：集成测试覆盖 ✅。

### 链路 3：排名积分（查表 + legacy 零变化 + 退赛豁免）
- `GroupStandingEngine.rank` 新 7 参重载，旧 6 参委托 `false`（存量调用方零变化；生产唯一入口 `TournamentRankingService.rankForGroup` 已传 `Boolean.TRUE.equals(division.getForceFullGames())`，191/555 两处调用点均经此包装器）。

## 三、观察项（不阻塞，建议知悉/择机处理）

1. **admin-web 无「打满三局」开关**（低）：admin-web 建排球赛时 payload 不含该字段 → 后端按 false 落库，行为安全。启用面仅小程序。若比赛由管理端建赛，需改到小程序开启或后续补 admin-web UI。与「admin-web 同步放开」仅指出线名额下拉的范围理解一致，非缺陷。
2. **镜像列读取的注释歧义**（极低）：V32 注释称「新代码不得读取」镜像列，但 `MatchRuleConfig.fromTournament` 读了——该路径仅为「比赛无组别」的异常数据兜底（V23 后理论不发生），且创建时镜像≡组别值，语义安全。属注释措辞与实现的边界解释问题，建议后续清理时统一口径。
3. **排球团体赛（非接力模板）子场继承父场 scope 规则**（备忘）：若排球团体小组赛开启打满三局，子场经 parent scope 解析同样强制，属预期传导而非缺陷；接力模板创建侧已显式 false。
4. **测试计数未复核**：后端 521 / 前端 501 / 三端构建为实施侧转述，按用户要求本轮未重跑（用户已自行跑绿）。
