## 2. 排球混沌体系地图（照此结构建羽毛球的）

```
测试内核          scoreboard-fuzzer.js        PRNG 场景生成 + 动作循环 + 不变式审计 + 批量入口
环境垫片          fuzzer-env.js               mock uni 全局 / onLoad 捕获 / storage
批量测试          scoreboard-fuzzer.test.js   vitest 入口（单场冒烟 + N 场批量 + 落盘）
页面流混沌        lineup-flow-fuzzer.test.js   真实跨局生命周期 + 回退重填恢复路径
分块编排器        scripts/run-fuzz-batch.mjs   百场分块 / 块级超时 / 断点续跑 / 环境变量透传
夜间 runner       scripts/run-night-chaos.mjs  进程锁 / 三层轮换 / 评估 journal（执行侧）
赛制引擎混沌      backend/.../TournamentEngineChaosTest.java   已存在，羽毛球复用
审查文档          docs/排球混沌测试夜间审查报告.md   人类可读追加式 + 审查清单
```

**排球动作分布（最终版，供参考）**：68% 得分 / 12% 撤销（8% 深撤销 3~5 步）/
12% 换人 / 5% 暂停 / 3% 恶意换人探针；2% 概率"杀进程重入"（仅稳定执裁态）；
换边弹窗 20% 走"保持本半场"。种子公式 `matchSeed = baseSeed + i × 9973`（i 从 1），
批次间种子段步进 1000 万，永无重叠。

**不变式审计器必须覆盖的类别**（排球版，羽毛球按规则改写）：
1. 阵容完整性（人数/唯一性/名册归属 FOREIGN_PLAYER）；
2. 项目特有硬规则（排球：自由人前排/队长；羽毛球：见 P0 调研）；
3. 比分与终局断言（达到 21 分且领先 2、或 30 封顶；局胜/场胜）；
4. 历史栈深度；
5. **发球轮转一致性**（SERVE_ROTATION_MISMATCH：回合胜方=下一发球方；
   排球实测这条审计器初版漏了，靠专项补上——羽毛球从第一版就要有）；
6. **恶意输入探针**（HOSTILE_INPUT_ACCEPTED/THREW：直接向状态机喂非法输入，
   断言其拒绝。注意判定只看"被攻击侧"，球员出现在自己半场不算）；
7. 覆盖度统计块（reloads/分支计数/局数直方图——"全净"必须附带覆盖证据，
   否则证明力不足）。

## 3. 两天实战踩坑全集（★最重要的一节，逐条规避）

这些全是真实发生过的缺陷/事故，每条都花了夜间值守一轮去定位：

1. **重入微任务竞态**：页面 onLoad 处理器在 `loadMatch()`（fire-and-forget）
   完成前就返回。重入后立刻提取快照 = 空场地（2/100 场命中，间歇性）。
   → **规避**：重入后循环"冲刷微任务 + 推进假时钟"，直到场地就位
   （`await Promise.resolve()` 若干次；`vi.advanceTimersByTime` 不冲刷微任务）。
2. **过渡窗口重入**：局间过渡期（lineupReady=false）重入会走"全新填写"分支
   （设计内正确），空场状态被 persistState 固化、自我延续到终局（3/100 场）。
   → **规避**：重入仅在稳定执裁态触发（lineupReady 且无过渡/弹窗）。
3. **僵尸 persistState**：页面卸载不清理挂起的"事件冲刷定时器"，跳转后定时器
   在已销毁实例上触发，把旧状态写回 storage 覆盖新状态（真实产品隐患）。
   → **规避**：实例销毁前 `vi.clearAllTimers()`；发现产品侧同类问题只登记不修。
4. **onLoad 处理器是每次实例构造时重新注册的**：重入/多实例场景必须取
   **最新注册**的处理器，旧处理器绑定在已销毁实例上（第一版踩过，症状=全空）。
5. **快照里没有花名册引用**：状态快照只含坐标/比分/标记，队伍名册在快照之外。
   任何"换边/恢复后名册与球场是否对齐"的断言必须按屏侧+名册单独校验
   （排球 §5.1.1 的核心教训）。
6. **内存管理**：每个动作产生数 MB 浮动垃圾（全量状态序列化）。批量必须：
   每场 `effectScope` 包裹 + `scope.stop()` + `vi.clearAllTimers()` +
   `vi.clearAllMocks()`（只清调用记录，不清 mockImplementation）+
   `uni.clearStorageSync()` + 强制 `gc()`（编排器需 `--expose-gc`）。
   排球 100 场实测堆 ~1.5GB / 上限 4GB。
7. **超时公式**：`30000 + 每场耗时余量 × 场数` 毫秒。排球最终 60s/场
   （含重入开销 ~2-3s/次）。羽毛球请先实测单场再定，**留 ≥30% 余量**，
   编排器块级超时再放大（排球 150min）。
8. **产物目录隔离**：单测冒烟与夜间批量共用同一测试文件——必须用
   `FUZZ_SUMMARY_DIR` 类环境变量区分落盘目录，否则冒烟小样覆写批量合并视图
   （排球 §5.3.3 真实事故 + 09-18 凌晨复发一次，夜间评估读到 0 场假数据）。
9. **npx 陷阱**：在仓库根目录跑 `npx vitest` 会现场安装 vitest@5 并失败。
   一律 `cd frontend && npx vitest run <file>` 或 `npm --prefix frontend test`。
10. **审计器初版漏发球轮转**：动作历史里记了 serveBefore/serveAfter 却没有
    断言它——"全净"了 900 场也证明不了轮转正确。**新写审计器时把这类
    "记了但没断言"的字段全部补上断言**。
11. **确定性**：一切随机必须走种子化 PRNG（禁止裸 `Math.random` /
    未播种 shuffle，否则无法确定性重放）。异常对象统一
    `{severity:'CRITICAL'|'SUSPICIOUS', type, message}`。
12. **根目录合并视图 vs chunk 归档**：合并视图=最后一次运行语义，且编排器
    合并时不含 coverage（coverage 只在 chunk 归档 summary 里）。评估逻辑
    要读对文件；冒烟与批量必须目录隔离（见第 8 条）。
