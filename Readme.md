# Badminton Scoring — 球类赛事计分小程序

## 一、项目概况

一个面向高中、大学班赛院赛、社会俱乐部小比赛的**球类赛事计分微信小程序**。目前已羽毛球为切入点，提供**实时记分牌**和**赛程管理**两大核心功能，解决传统手写记分表、Excel 排赛程的低效问题。

## 二、技术栈

| 层级 | 技术 | 选型理由 |
|------|------|---------|
| 前端框架 | uni-app (Vue 3) | 一套代码编译到微信小程序 + H5，跨端成本低 |
| 后端框架 | Spring Boot 3.3.5 | 主流 Java 框架，生态成熟 |
| ORM | MyBatis-Plus 3.5.7 | 代码简洁，提供分页、自动填充等开箱即用功能 |
| 数据库 | MySQL | 轻型结构化数据，适合赛事管理场景 |
| 工具库 | Hutool 5.8.30 | 集合、字符串、ID 生成等工具方法，减少重复代码 |
| 构建 | Maven | 标准 Java 项目构建工具 |

## 三、系统架构

```
小程序端 (uni-app)
    ↕ HTTP API
后端 (Spring Boot)
  ├─ Controller 层 — 接收请求、参数校验
  ├─ Service 层   — 业务逻辑编排、事务管理
  ├─ Engine 层    — 核心算法（签表生成）
  ├─ Mapper 层    — 数据库访问 (MyBatis-Plus)
  └─ MySQL        — 数据持久化
```

**包结构：**

- `controller/` — RESTful 接口
- `service/` — 业务接口 + 实现
- `engine/` — 淘汰赛签表生成算法
- `domain/entity/` — 数据实体
- `domain/dto/` — 请求参数
- `domain/vo/` — 响应视图
- `common/` — 统一响应、全局异常处理
- `config/` — MyBatis-Plus 自动填充配置

## 四、功能模块

### 模块 1：记分牌（Scoreboard）

前端独立运行，通过 `uni.setStorageSync` 实现本地持久化，支持"离线操作、云端同步"。

- **加分**：点击任意一方分数面板 +1 分，发球权自动切换
- **撤销**：基于历史快照栈（historyStack）实现多步撤销
- **换边**：交换左右队伍名称、分数和发球权
- **退赛**：弹出确认框，记录退赛方与胜方，显示比赛用时
- **结束比赛**：比较分数判定胜方，展示结算卡片
- **上帝模式**：开启后在面板上方显示 +/- 按钮，可手动调整任意分数（应对非标准计分场景）
- **本地状态恢复**：页面加载时自动从 Storage 恢复上一次的完整比赛状态

### 模块 2：赛程管理（Tournament）

后端负责赛事全生命周期管理。

- **创建赛事**：输入赛事名称、地点、参赛选手列表；后端校验后写入数据库；自动生成淘汰赛签表
- **查看签表**：返回赛事基本信息 + 选手列表 + 所有轮的比赛对阵
- **上传赛果**：提交比分展示字符串 + 胜方 ID；更新当前比赛状态；自动晋级胜方至下一轮；若为决赛，将赛事标记为已结束
- **赛事列表**：按创建时间倒序展示所有赛事

## 五、技术亮点（面试重点）

### 1. 淘汰赛签表生成算法 — `BracketEngine`

递归算法，核心思路：

- **容量对齐**：选手数 n → 向上取整到 2 的幂 p
- **种子序号排列**：递归构建平衡二叉树种子序列 —— 每对相邻种子和为 p+1
- **随机打乱**：选手顺序随机 shuffle 后按种子槽位填入
- **轮空自动坍缩**：第一轮若某个对阵仅有一方存在，自动将其判胜并晋级到下一轮
- **双向链表式串联**：每场比赛记录 `next_match_id` + `next_match_slot`（left/right），形成天然的晋级链路；上传赛果时直接根据此链找到下一轮对阵并填入胜方

**为什么这么设计？** 相比一次性生成完整树 + 赛后递归重算，这种设计让每场比赛独立更新、职责单一，在多场比赛并行进行时互不干扰。

### 2. 记分牌撤销功能的实现

使用**快照栈模式**：每次操作前将完整状态（双方分数、发球权、队名等）压入 `historyStack`，撤销时弹栈恢复。相比事件溯源或增量记录，实现简单、容错性强，适合小程序离线场景。

### 3. 上帝模式（God Mode）

解决实际比赛中可能出现的非标准情况（如裁判误操作、特殊规则）。开启后允许精细调整 ±1 分，作为标准加分流程的兜底方案。

### 4. 统一异常处理

`@RestControllerAdvice` + `GlobalExceptionHandler` 统一拦截：
- `IllegalArgumentException` → 400（业务参数错误）
- `IllegalStateException` → 500（数据状态异常）
- `MethodArgumentNotValidException` → 400（参数校验失败）
- `Exception` → 500（未知异常）

前端统一按 `ApiResponse.code` 判断成功/失败，清晰一致。

### 5. 事务管理

创建赛事（插入赛事 → 批量插入选手 → 生成签表 → 批量插入比赛记录）和上传赛果（更新当前比赛 → 更新下一轮对阵）均在 `@Transactional` 中执行，保证数据一致性。

## 七、

### 项目背景（30 秒）
"这个项目源于我在学校参加羽毛球比赛时的实际痛点 —— 手写记分表麻烦、赛程用 Excel 展示不直观。所以我做了一个微信小程序，解决小规模球类比赛的记分和赛程管理问题。"

### 挑最有技术含量的点讲（2-3 分钟）
重点讲 **BracketEngine**：
"我花最多心思的是淘汰赛签表引擎。它不是简单地随机分组，而是用了递归种子排序算法 —— 保证强选手在决赛前不会相遇。而且设计了晋级链表的机制，每场比赛记录下一场的 ID 和左右位置，这样多场比赛可以独立上报结果，系统自动推导晋级路径。这个结构也天然支持并发 —— 多台设备同时打不同场次的比赛不会冲突。"

### 体现工程意识（1 分钟）
"我做了统一的异常处理、参数校验、事务管理这些基础工程。记分牌支持本地离线缓存、页面关闭后再打开能恢复。虽然项目不大，但在代码质量上我对自己的要求比较高。"

### 如果有余力聊后续规划
"接下来计划做循环赛支持、团队赛模式，以及赛后数据统计复盘，比如得分趋势、发球得分率这些。"
